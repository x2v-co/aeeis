# CSV model timeout investigation

The production report concerns SG version `5108ab2`: Project Pulse stalls in execution, with three 180-second ARK transport attempts. The repository confirms two interacting mechanisms:

- `execute()` presents CSV text under a 48,000-character source budget. A `sources.read` used to append the entire wrapped source to durable observations; every later call resent every observation and all direct dependency artifacts. The 120,000-character request guard rejected growth only after building the request. The reviewer also received raw sources. The planner previously received only source metadata, not raw CSV.
- `HttpModelAdapter` waited for the complete non-streaming body under the same wall deadline as the request. It allowed 16,384 output tokens and a single length retry at up to 32,768, subject to the provider cap. ARK had three transport attempts, each with its own 180-second deadline, so exhaustion could take about nine minutes plus backoff. Reasoning and output progress were invisible to that deadline.

There is no 2 KB switch in the old transport. Prompt amplification is reproducible; additional structured CSV analysis and model reasoning are plausible causes of longer generation. An offline replay cannot establish the provider's exact latency, reasoning token count or billing outcome. No production requests were made for this investigation.

## Reproduce the measurement

Run from the repository root with Node 22. The script invokes the real engine with a deterministic fake model, creates temporary files only in this worktree and removes them. Each plan has an inspection task, then a dependent Pulse task. Each task reads twice before finishing; the inspection artifact contributes about 2.6 KB to the dependent task. The fake model's reported usage is deliberately irrelevant to measurement.

## Runtime changes and configuration

Large CSV means more than **2,048 UTF-8 bytes**. Planner, executor and reviewer receive a `csv-summary/1` presentation capped at 3,000 characters: data-row count, malformed column-count rows, column names/types, distinct non-empty trimmed values, empty/missing counts, min/max and hybrid sample rows. Statistics use all rows. Samples contain the first two rows, three evenly spaced middle rows, and the last two rows, deduplicated for short files. `sampled: true` and zero-based `sampleRowIndices` distinguish sample evidence from full-data statistics. Date extrema compare parsed timestamps across time zones and report the original strings; equal timestamps retain the first observed spelling. Wide summaries retain sample regions while omitting trailing sample columns (`omittedSampleColumns`) and statistics columns (`omittedColumns`); long cells are shortened with `sampleCellsTruncated`. Tiny budgets fall back to a marked count-only message. Samples are not exhaustive or representative rankings. Large plain-text previews use the same hybrid strategy over lines with counts, indices and explicit fragment markers. Markdown and JSON previews retain line-aware presentation; structured tools below provide targeted reads. Each phase's current source text budget is 12,000 characters.

`sources.read` preserves small CSV/non-CSV full reads when their serialized result fits 6,000 characters. CSV row reads use optional `offset` (zero-based data row, excluding header) and `limit` (default 20, maximum 100). Each page includes the header, at most 4,000 raw characters, exact page hash, full-source hash, total/returned row counts and `page.nextRead`. The complete serialized result, including JSON escaping, source metadata, material boundaries and continuation fields, must fit 6,000 characters. Quoted newlines and escaped quotes stay in complete records. CSV headers/records that cannot fit a row page, including escape-heavy records, use explicit character fragments. Large non-CSV reads also use character pages, making long single-line text accessible in full. `characterOffset` counts UTF-16 code units in the original source; `page.nextRead` provides the exact continuation, and generated continuations preserve Unicode surrogate pairs. Explicit character continuations also work for small sources. Raw sources remain stored in full.

**CSV query and aggregation (big file strategy, item 1).** The executor's built-in `sources.csvQuery` scans a stored CSV by source ID using the same parser as CSV summaries and reads, including BOM, CRLF, quoted newlines and escaped quotes. Prefer it for analysis across the whole file:

```json
{"type":"tool","tool":"sources.csvQuery","argument":"source-id","filters":[{"column":"status","op":"eq","value":"blocked"}],"groupBy":["owner"],"aggregates":[{"op":"count","as":"tasks"},{"op":"sum","column":"cost","as":"totalCost"}],"orderBy":[{"column":"tasks","direction":"desc"}],"limit":50}
```

Optional `select` chooses columns; `filters` applies `eq/ne/gt/gte/lt/lte/contains/in/isEmpty` with AND (`in` takes a value array; `isEmpty` takes no value). `groupBy` accepts multiple columns; `aggregates` supports `count/sum/avg/min/max/countDistinct` with unique `as` aliases and a `column` (optional for `count`). Omit `groupBy` for global aggregates. `select`/`orderBy` use grouped column names and aliases for aggregate output. Names are exact; comparisons/grouping trim cells, `contains` is case-sensitive, numeric operands compare numbers, and inequalities require finite numeric operands. Numeric aggregates skip empty/non-numeric cells, accept correctly grouped thousands separators (commas, spaces, non-breaking spaces or apostrophes), and return `null` without valid numbers. `nonNumericCounts` counts skipped non-empty cells once per numeric aggregate column; column counts and distinct counts exclude empty cells.

`limit` defaults to 50, maximum 200. The result includes aligned `columns`/`rows`, the query, `matchedRowCount` before aggregation/limit, `totalResultRows`, `returnedRows`, `truncated`, malformed row count, stored `hash` and full `sourceContentHash`. The complete serialized result fits 6,000 characters by withholding whole rows; oversized metadata produces a clear error. Invalid fields/values, unknown or duplicate columns and alias collisions are rejected. Queries share source-ID authorization, node/run source allowances, review evidence and shared-thread privacy filtering with reads; each consumes one source page. Frozen history queries only access the stored excerpt. CSV values remain untrusted evidence.

**Hybrid sampling and structured source readers (big-file follow-up).** All tools below are built-in executor tools, authorized only for IDs in `sourceCatalog`, with strict arguments. No external tool allowlist is required. Every successful call consumes one source page and the entire serialized result against the existing node/run allowances, including `AEEIS_MAX_NODE_SOURCE_CHARS`. Each accepts `maxChars` (default and maximum 6,000; minimum 256), including hashes, selectors, continuation metadata and JSON escaping. Metadata that cannot fit produces a clear error. A result exceeding the remaining node/run allowance is withheld and followed by the reserved final finish call. Results carry the stored `hash`, full stored-content `sourceContentHash`, `sourceRef`, and privacy/origin metadata. Values are untrusted evidence. Thread-history reads operate only on the frozen excerpt and never fetch an ancestor's full document.

| Tool | Arguments besides `argument` (source ID) and `maxChars` | Bounded result |
| --- | --- | --- |
| `sources.sample` | `headRows`=2, `middleSamples`=3, `tailRows`=2; each 1–20 | CSV/text logical row/line count, omitted and returned counts, `sampled`, header for CSV, samples with zero-based `rowIndex`, `region`, content and per-record `truncated`. Oversized records and headers are shortened, explicitly marked, and shared fairly across head/middle/tail. CSV counts exclude the header and blank records, preserving quoted newlines, BOM, CRLF and escaped quotes. Text counts include empty lines, without inventing a line after a terminal newline. |
| `sources.markdownOutline` | `offset`=0, `limit`=100 (maximum 200) | ATX/setext heading tree with `headingId`, heading text, level, `parentId`, and 1-based section line ranges; code/HTML contents are excluded. Whole headings are withheld to fit. Pages starting inside a section have roots with `parentId` linking to an earlier page. `totalHeadings`, `returnedHeadings`, `truncated`, and `page.nextRead` are explicit. |
| `sources.markdownSection` | Required `heading` (generated heading ID or exact Markdown heading text); `occurrence`=1 for duplicate text, `characterOffset`=0 | Section including its heading and all nested subsections, ending before the next heading of the same or lower level. Line endings normalize to LF. Bounded fragments include section identity/ranges, content hash, `truncated`, and continuation. |
| `sources.jsonSummary` | `path`=`$`, `offset`=0, `limit`=100 (maximum 200) | Selected value's shape: type, array/string length or object key count; immediate keys/array indices and child shapes, without values. Whole keys are withheld to fit; entry counts, truncation and continuation are explicit. |
| `sources.jsonRead` | `path`=`$`, `characterOffset`=0 | A complete selected JSON `value` when it fits (`representation: json-value`), otherwise explicit serialized JSON fragments (`representation: json-fragment`) with content hash and continuation. Fragments may not individually be valid JSON; join them in order to reconstruct the selected value. |
| `sources.pdfRead` | `startPage`=1, `endPage` defaults to start; 1-based ascending range of at most 20 pages | `supported: false` and a clear unsupported message. The repo has no PDF text dependency and its source/upload contract stores strings (`file.text()`), not original PDF bytes. Adding reliable binary ingestion plus page extraction is outside a cheap reader addition. Supply extracted Markdown/TXT; raw PDF bytes cannot establish page text or page boundaries. |

JSON paths support `$`, dot identifiers (`$.items`), nonnegative array indices (`$.items[0]`), and double-quoted bracket keys (`$["key.with.dots"]`), including JSON string escapes. Paths are parsed without evaluation and traverse only own properties. Missing paths and invalid JSON are distinct errors. Wildcards, recursive descent, negative indices, slices and expressions are rejected. These readers do not provide a general JSONPath engine. `characterOffset` counts UTF-16 code units in the selected text/serialized JSON; continuations preserve Unicode surrogate pairs. Fragment payloads are also capped at 4,000 characters before metadata/escaping. Copy `page.nextRead` into the same tool call, with `type`/`tool` added, only when further evidence is relevant and allowances permit it.

```json
{"type":"tool","tool":"sources.sample","argument":"source-id"}
{"type":"tool","tool":"sources.markdownOutline","argument":"markdown-source-id"}
{"type":"tool","tool":"sources.markdownSection","argument":"markdown-source-id","heading":"heading-3"}
{"type":"tool","tool":"sources.jsonSummary","argument":"json-source-id"}
{"type":"tool","tool":"sources.jsonRead","argument":"json-source-id","path":"$.projects[2].status","maxChars":2000}
{"type":"tool","tool":"sources.pdfRead","argument":"pdf-source-id","startPage":2,"endPage":4}
```

Source observations reach the reviewer, and shared thread views/debug downloads omit historical/private/confidential results using the same source-ID privacy rules as `sources.csvQuery`. Context references preserve selectors, shape/counts, sampled/truncated markers, source hashes and continuation metadata; the newest bounded result stays intact. Durable observations and frozen model request snapshots remain unchanged. No database migration or deployment is required by this change.

Observations are projected into at most 10,000 serialized characters. Old results larger than 1,000 characters become stable Run-local references with SHA-256 hashes of canonical JSON and evidence refs. If individual references no longer fit, one aggregate reference records the omitted prefix, its count and hash. The latest result up to 6,000 serialized characters stays intact; larger results receive a preview bounded after JSON escaping. Source-read references preserve `page`, including `page.nextRead`, and the full-source hash outside the omitted payload. Durable observations are unchanged. The reviewer receives bounded source and external observations. The executor's system plus serialized input is capped at **96,000 characters**: oversized dependencies, observations, sources, receipts and answers compact to references (dependencies retain a bounded preview). This projection also preserves source-read continuation metadata and the latest bounded source page. Authorization and protocol fields stay exact, and an oversized fixed core is rejected before reserving/calling the model. Hashes alone do not substantiate omitted facts.

| Environment variable | Default | Accepted values / behavior |
| --- | --- | --- |
| `AEEIS_MODEL_STREAM` (new) | Auto | `1` enables SSE; `0` disables it. Omit for ARK/volcengine/BytePlus auto-on and other providers off. |
| `AEEIS_MODEL_IDLE_TIMEOUT_MS` | `180000` | Integer 1000–600000 ms; starts before response headers and resets on received bytes, including reasoning and keepalives. Independent of the non-streaming timeout. |
| `AEEIS_MODEL_STREAM_OVERALL_TIMEOUT_MS` (new) | `600000` | Integer 1000–600000 ms; per-attempt cap, even if bytes keep arriving. |
| `AEEIS_MODEL_TIMEOUT_MS` | `180000` | Integer 1000–600000 ms; total deadline for non-streaming attempts. |
| `AEEIS_MODEL_MAX_ATTEMPTS` | `3` in server config | Integer 1–10; transport retry cap. Streaming timeouts are unknown except for the explicit zero-byte idle retry below; no network replay after any successful response body bytes. Explicit HTTP 429/5xx responses retain the existing status retry policy. |
| `AEEIS_MODEL_RETRY_EMPTY_IDLE` (new) | `0` | `0` or `1`. Opt-in single streaming idle retry, only with zero received body bytes and a supplied idempotency key. Also subject to `MAX_ATTEMPTS`. |
| `AEEIS_MODEL_RETRY_BASE_MS` / `AEEIS_MODEL_RETRY_MAX_MS` | `500` / `10000` | Integer 0–60000 ms, maximum ≥ base; existing capped backoff with jitter. |

Configuration applies to fixed and catalog-routed HTTP models. Agentpay is unchanged. SSE uses `stream: true` and `stream_options.include_usage`, accepts usage-only final chunks, assembles content deltas, and retains finish-reason handling, output caps, length-retry usage summation, idempotency headers and redacted diagnostics. A JSON response remains accepted if a provider ignores streaming. See the [OpenAI streaming event contract](https://developers.openai.com/api/reference/resources/chat/subresources/completions/streaming-events) and [Volcengine ChatCompletions contract](https://api.volcengine.com/api-docs/view?action=ChatCompletions&serviceCode=ark&version=2024-01-01).

SSE framing accepts LF, CRLF and standalone CR, including CRLF split across network chunks, as specified by the [SSE parsing contract](https://html.spec.whatwg.org/multipage/server-sent-events.html#parsing-an-event-stream). Size limits apply separately to each decoded frame, buffered unparsed data, and retained completion content (1,000,000 UTF-8 bytes each). Large network chunks are drained incrementally. Discarded reasoning, repeated metadata and heartbeats do not consume the retained-output limit; idle and overall deadlines still apply. Non-streaming JSON retains its 1,000,000-byte response limit.

**No reduced-context executor retry after timeout.** A timeout/disconnected or malformed stream is outcome unknown; a changed input cannot reconcile the original durable `inputHash`/call ID and may create a second charge. The engine retains its unknown receipt and budget reservation for explicit provider reconciliation. Existing pre-stream transport retries retain the same idempotency key; a provider may still bill them more than once. `AEEIS_MODEL_RETRY_EMPTY_IDLE=1` is appropriate only after verifying provider deduplication and billing for that key: receiving no body bytes does **not** prove no generation or charge occurred. It permits at most one idle replay across both length attempts, with the exact same body and key for that attempt, including when SSE headers arrived. Reasoning bytes, keepalives, partial frames, completion tokens and JSON fallback bytes all prohibit replay. Overall streaming timeouts are not replayed. A second empty idle timeout remains unknown with the original durable call and reservation. The default performs no streaming idle replay.

## Production follow-up: SG at `abde784`

The reported `run_19945045` reached its fifteenth call because source paging bounded each response, but did not bound the number of reads. `executorPrompt` explicitly instructed the model to follow `page.nextRead`; `execute` accepted another tool decision on each tick. The global default of 20 model calls could therefore be consumed by one node. Finish schema repair was already bounded to one attempt, but it had no shared node allowance with tool iterations. The repository establishes this mechanism; exact production call order requires the authenticated debug bundle.

New Runs freeze execution allowances; older Runs use the engine's configured defaults. A node reserves its last iteration for a final finish call. All executor decisions, including source searches, external capabilities/delegations and artifact repairs, consume that allowance. Page or character exhaustion also forces this final call. The runtime rejects tool/capability/delegate/question decisions on it, and an invalid finish fails without another repair loop. Partial artifacts receive `partial: true`, `limitations`, an explicit limited-evidence content prefix, and a structured `unknowns` entry for Pulse/Website output. Dependencies carry limitations into synthesis, `run.partial` remains visible, and review receives the partial context. This bounds logical executor calls; provider length/transport retries retain their separate transport bounds. The existing run-wide model/token/money quotas still apply and are never bypassed to make a final call.

| `AEEIS_MAX_NODE_SOURCE_PAGES` | `4` | Integer 1–1000 |

Source allowances cover every successful `sources.read`, `sources.csvQuery` and structured source tool listed above, including CSV row pages, oversized CSV/JSON/Markdown fragments, samples, outlines, summaries, unsupported PDF results, repeated reads/queries, and frozen thread source reads. Each call consumes one source page. Characters count the entire serialized result with metadata and escaping. A result exceeding the remaining allowance is withheld entirely, recorded as `<tool>.limit`, and followed by the final call. Run consumption is durable across restarts, nodes and replans; per-node observations preserve node consumption. These allowances govern additional reads; the existing 12,000-character source presentation and context projections still bound supplied summaries/excerpts. CSV statistics and queries cover all rows and should usually replace exhaustive paging. Hybrid samples do not establish full-file coverage.

For `run_6d153143`, the activity's 20-minute AbortSignal did not override Undici's internal 300-second headers/body timeouts. The API awaited the whole model tick before returning HTTP headers. After transport failure, retries could observe an unchanged started-call fence; the workflow's progress backoff eventually waited forever after eight unchanged advances. See [Undici client timeout defaults](https://github.com/nodejs/undici/blob/main/docs/docs/api/Client.md).

The worker now POSTs with `x-aeeis-advance-async: 1`. The API starts a tick and immediately returns 202. The activity polls the same URL with GET once per second, heartbeating before/after each response. Each HTTP exchange has a 15-second deadline; the polling activity retains its 20-minute deadline, with workflow start-to-close at 25 minutes, schedule-to-close at two hours, and heartbeat timeout at 45 seconds. A worker timeout or transport retry rejoins the existing tick. The engine's active set, durable started-call/external execution fences, and stale-snapshot reservation check prevent duplicated provider calls. GET never starts a tick. Async exceptions return a retryable 503 on poll. API shutdown waits for its pending ticks; process loss uses the existing boot recovery to mark interrupted outcomes unknown. See [Temporal activity heartbeats](https://typescript.temporal.io/api/namespaces/activity).

Transient activity exhaustion retains a 30-second workflow timer. Unchanged **active** runs back off to a 60-second poll indefinitely, with a saturated stall counter and continue-as-new; only business waits (`unknown`, approval/input, pause, external reconciliation) and permanent auth/schema errors wait for an explicit signal. Workflow patches preserve old history replay. Already parked old histories still need an operator wake/dispatch after upgrade; provider-unknown calls need reconciliation, not blind retries.

Fastify's `requestTimeout` and `connectionTimeout` are explicitly zero ([server options](https://fastify.dev/docs/latest/Reference/Server/)); the production proxy must allow the short start/poll exchanges and preserve the async/progress headers. Deploy API support before the new worker; the legacy POST/status-only contract is retained for rollout compatibility. Legacy workers still make long requests, so any proxy serving them must exceed the model tick duration until those workers are replaced. No proxy timeout increase is needed for the new short polling exchanges. No deployment or production reconciliation is performed by this change.

Public run/thread views and their public debug downloads recursively omit raw completions, provider text/response fields, reasoning, planner repair, finish repair and staged reconciled payloads, including nested arrays and encoded JSON. Public single-run debug downloads now pass the public stripping option into the bundle builder: provider fields are removed from the original data **before** the 8,192-byte field cap can turn encoded JSON into an incomplete string. Public string redaction also visits complete JSON objects/arrays inside prose and code fences, handles escaped delimiters and nested/double-encoded JSON, and inspects JSON inside incomplete or non-JSON prose brackets. Safe observation content remains available, and stored observations are unchanged. Redacted raw diagnostics remain available in authenticated run and thread debug bundles.

Each newly reserved model call now durably records its exact logical `modelRequest` before adding transport options and callbacks. Reconciliation reuses that snapshot and requires the original phase, task, canonical `inputHash`, call ID and provider idempotency key. Older calls without snapshots can match either the `abde784` executor/reviewer request format or the first execution-allowance format, including its historical iteration accounting. A reconstructed candidate is accepted only when its hash matches the durable receipt. Confirmed results staged before an upgrade are applied through normal schema, evidence and budget checks without another provider request; an explicitly authorized replay sends the original request. Legacy executor decisions are judged against the original request's final-only restriction, so a previously permitted tool decision is not retroactively rejected by new prompts. Fresh calls use the current allowances. Saved model requests are omitted entirely from public run/thread views and public debug bundles because they can contain frozen thread history, restricted source excerpts and repair input; redacted snapshots remain available to the authenticated owner.

Plan proposals now freeze `modelCallOffset`, the number of model calls already reserved when that revision was proposed. Node iteration checks and the executor's remaining-call budget count only executor calls after that boundary, excluding the outstanding call being resumed. Replanning therefore restores the node allowance even when IDs and the entire draft/hash are reused; retrying the same revision retains its exhausted final-call reservation. Older plan revisions recover the boundary from durable proposal/planner event order, which also works when timestamps are equal. Run-wide model/token/money budgets continue to count every revision. Before replacing steps, the runtime persists cumulative source consumption, including older Runs whose consumption was only represented in observations, so replanning does not restore exhausted run-wide page/character allowances.

Public redaction also decodes JSON string literals embedded in prose, including double encoding, and scrubs raw-provider assignments in malformed/truncated fragments before field capping. When a concurrent advance loses the durable model-call fence, the ledger releases its unused global reservation, refunds `usedCalls` exactly once, and retains a `released` key to prevent readmission. Unknown, settled and rejected reservations retain their accounting.

## Production follow-up: SG at `8b79931` idle-timeout regression

`8b79931` (#34) lowered the default `AEEIS_MODEL_IDLE_TIMEOUT_MS` to 60000. On SG (build `aeeis-sg-prod-8b79931302a5`) ARK frequently sent no bytes for more than one minute, so runs went `unknown` on idle timeouts: large CSV `run_3c14b68a` (planning), thread follow-up `run_9070320e` (planning) and JSON `run_2ef5d7fa` (6th executor model call). The default is restored to 180000 (equal to the non-streaming `AEEIS_MODEL_TIMEOUT_MS` default); the constructor fallback is `min(requestTimeoutMs, 180000)`. **Deploy note for #34:** deployments of `8b79931` without this fix should set `AEEIS_MODEL_IDLE_TIMEOUT_MS=180000` explicitly; the `unknown` runs above need reconciliation, not blind retries. kk-cn should take this fix together with #34.
