# 别人也能和你的 Bot 说话

「Bot 当成员」阶段 1、2 已上线（#256、#258、#259）。那份设计第 6 节把这件事留到以后，说要和「加用户」、隐私页一起单独设计。这份就是它。

## 0. 现在是什么样

**身份。** 一个人是一个 Principal：`{ id, tenantId, roles }`（`src/security/principal.ts`）。数据按「主人范围」`{ owner, tenantId }` 存。生产用 Google 登录：`AEEIS_GOOGLE_USERS` 把邮箱映射成 Principal，也可以按域名放行，域名里的人进同一个 `AEEIS_GOOGLE_DOMAIN_TENANT`（`src/security/google-signin.ts`）。今天生产只有一个人（owner/local）。Google 同意屏幕还在测试状态，每个新用户都要在控制台加成测试用户；要正式发布，Google 要一个隐私政策链接。

**Bot。** 自建的 Bot 存 `owner`、`tenantId`、名字、背景、角色、自主程度（`src/owned-bots.ts`）。和一位 Bot 的一对一是它的对话，按主人范围 + agentId 一条，绑着一间私聊房间。凡是按 id 找 Bot 的地方都核对主人范围，别人拿到的是「Unknown Bot」（`BotDialogueService.bot`，`src/application/bot-dialogue-service.ts:42`；`ConversationService`，`src/application/conversation-service.ts:962`）。

**工具。** Bot 自己**没有**工具授权。工具是每个 Run 的 `allowedTools`：界面按 `AEEIS_DEFAULT_ALLOWED_TOOLS` 预填（生产是 `web-search@1`、`web-fetch@1`），例程在自己的 `runOptions` 里写。Run 创建时冻结成能力目录，执行时没批准的工具一律不跑（#260 之后是退回给模型重来，不再结束 Run）。有副作用的动作另受主人的「行动策略」管（`src/action-policy-store.ts`）。Bot 电脑按人限台数（`perPrincipal.maxMachines`，生产是 3）。

**额度和加密。** 全局额度按租户算（`src/global-budget.ts`）。内容加密每个租户一把数据密钥（`src/content-encryption.ts`）。

**群里已经有别人。** 房间可以邀请同租户的人当 `editor` / `viewer`，邀请时用目录核对对方存在、同租户、在用（README「Room」一节）。但群里 Bot 的回复和分派走的是**房间主人**的路径（`src/bot-team.ts` 开头的说明），所以今天别人在群里 @ 你的 Bot，算的是你的范围和额度，用的是你给 Run 的工具。这是阶段 3 必须先收紧的一处。

## 1. 原则

沿用阶段 1 的「问三件事」，这次三件事落在两个人身上：

1. **谁在请它做**：请求人。Run、对话、记忆都记在请求人范围里，用请求人的额度。
2. **Bot 被允许做什么**：主人定上限。请求人只能在主人开放的范围里收窄，不能放宽。
3. **在哪里说的，决定谁看得见**：一对一只有请求人和这位 Bot；群里按房间成员。主人**看不到**别人和主人的 Bot 的一对一内容。

再加两条：

- **不跨租户。** 「别人」只指同一租户里的人。跨租户意味着跨加密密钥、跨额度、跨目录，不在这一阶段。
- **默认关。** 一位 Bot 不开放，别人就看不到它，和今天一样。

## 2. 谁是「别人」：加用户

阶段 3 之前得先能有第二个人。今天加人要改 `stack.env` 再部署，还要去 Google 控制台加测试用户。

- **3a 只做最小的一步：** 主人在「设置 → 成员」里看到本租户的人（来自 `AEEIS_GOOGLE_USERS` 和域名登录过的人），能给每人一个显示名。加人仍然靠配置，界面上写清楚「请管理员把邮箱加进来」。不做自助邀请、不做邀请链接。
- **人的档案页**（阶段 1 已经做成人和 Bot 共用）开始出现别人：名字、头像、和你共同的群聊。
- **隐私页**：一页公开的 `/privacy`，说清 AEEIS 存什么、谁能看、怎么删。有了它才能让 Google 同意屏幕从测试转正式，也是别人用你 Bot 之前必须能看到的东西（第 6 节）。

自助邀请、角色管理、移出成员后数据怎么办，另写「加用户」设计，不在这里展开。

## 3. 主人开放一位 Bot

Bot 档案页加一栏「对别人开放」，默认关。打开后填三样：

| 项 | 默认 | 说明 |
|---|---|---|
| 谁能用 | 本租户所有人 | 也可以只列几个人 |
| 对别人开放的工具 | 只读的那些 | 从主人自己能用的工具里勾。「只读」= 能力只有 `read`（和 `network` 读网页）；带 `write` 的默认不勾，勾上要再确认一次 |
| 别人看得到的介绍 | Bot 的名字、角色、背景 | 背景可以另写一份给别人看的，不填就用原来的 |

存成 Bot 上的一份「开放设置」`{ audience, tools, publicBackground?, updatedAt }`，跟着 Bot 记在主人范围里。改了立即生效，下一个 Run 按新的来；已经在跑的 Run 不受影响（和行动策略一样，创建时冻结）。

**不开放的东西**：主人的常驻嘱咐、主人和这位 Bot 的对话和记忆、主人的例程、Bot 电脑、主人的行动策略里「允许」的那些动作。

## 4. 别人和这位 Bot 一对一

### 4.1 对话存在哪

**存在请求人范围里**：每个「请求人 × Bot」一条对话，`owner` 是请求人，`agentId` 是 Bot id，另记 `botOwner`。理由：

- 这是请求人的聊天，出现在请求人的「消息」列表里，未读、摘要、通知、加密都按请求人范围走，阶段 1 的东西不用改。
- 主人看不到内容，靠的是范围隔离本身，不靠界面上藏起来。
- 请求人删自己的聊天、以后移出成员，都只动请求人范围。

它也要一间绑定的私聊房间（对话写入前要检查房间可写），房间主人是请求人，成员是请求人和这位 Bot。

### 4.2 Bot 读什么、写什么

| | 读 | 写 |
|---|---|---|
| 主人范围 | Bot 的名字、角色、开放设置、给别人看的背景（只读，每次 Run 开始时取一份快照） | 只写用量记账（第 5 节），不写内容 |
| 请求人范围 | 这条对话、它的工作记忆、请求人给的资料 | 消息、任务、Run、产物、工作记忆 |

主人的长期记忆（brain）和主人与 Bot 的对话**不读**：那里面是主人的事，读进来就可能在回答里说给别人听。以后如果要让 Bot 带着主人的知识回答别人，做成主人明确挑出来的「对外资料」，不是整个记忆。

### 4.3 Run 的权限

请求人在这条对话里开的 Run：

- 记在请求人范围，扣请求人所在租户的额度（同租户，和今天一样是一个池子），并记到第 5 节的计数上。
- `allowedTools` = 请求人这次选的 ∩ 主人开放的工具。服务端算交集，不信页面传来的。
- 自主程度封顶 `reply`：Bot 可以回答、提议，开 Run 要请求人自己批准计划；主人给 Bot 设的 `auto` / `yolo` 不带过来。
- 行动策略用**请求人**的（请求人自己的副作用自己批），但工具清单已经被主人收窄过，带写入的工具除非主人勾了，根本进不来。
- 不能用 Bot 电脑。

### 4.4 撤回开放、撤下 Bot

- 主人关掉开放或把某人移出名单：请求人的这条对话变成只读，留历史，标「已不再开放」；进行中的 Run 跑完为止，不再开新的。
- Bot 撤下：和今天一样，只读、标「已撤下」。
- 请求人那边的历史一直归请求人，主人删不掉，也看不到。

## 5. 主人能看到什么

主人在 Bot 档案页看到「别人怎么用它」：每人一行，最近一次时间、本月 Run 数、本月 token。**没有内容**，不能点进去看对话。

请求人第一次打开别人的 Bot 时，看到一句说明：「这是 X 的 Bot。你们的对话只有你能看到；X 能看到你用了多少次、多少 token，看不到内容。」链接到隐私页。

**限额**：开放设置里可选「每人每月最多 N 个 Run」，默认不限。到了上限，Bot 照常回话，开 Run 时告诉请求人已到主人设的上限。全局额度仍按租户算，这只是主人分给别人的那一份。

## 6. 在群里

房间成员已经可以是别人。阶段 3 改的是**算谁的**：

- 群里谁 @ 一位 Bot、或「交给它」，就按**说话的人**算：Run 和讨论任务记在说话人范围里，工具按 4.3 收窄。今天一律按房间主人算，这要改，而且先于开放一对一上线（否则一开放，群里就是绕过开放设置的后门）。
- 说话人是这位 Bot 的主人：和今天完全一样。
- 说话人不是主人、Bot 没对这个人开放：Bot 在群里只做「只讨论」的回复（今天的规则），不记任务、不开 Run，并说一句「X 没有把我开放给你，可以请 X 来交给我」。
- 群里的回复谁都看得见。今天群里回复的模型输入是：这位 Bot 的名字、角色、背景、**常驻嘱咐**（`src/bot-team.ts:177` 的 `you.standing`），加上任务板和最近 30 条群消息；不读主人的长期记忆和主人与 Bot 的对话。常驻嘱咐是主人管自己 Bot 的办法，群里有别人时它照样生效，但模型可能把它说出来。草案：群里照旧用常驻嘱咐（这是主人的 Bot、主人建的或加入的群），档案页「常驻嘱咐」旁写明「在有别人的群里也会用到，别写不想让群友知道的事」；一对一给别人时不用（4.2）。见第 11 节第 6 条。

## 7. 不做的事

- 跨租户。
- 自助邀请、邀请链接、角色管理（另写「加用户」）。
- 别人用你的 Bot 电脑。
- 主人看别人对话的内容，哪怕是「管理员」。
- 别人改你 Bot 的名字、背景、自主程度、例程。
- 计费、给别人的用量开账单。

## 8. 阶段

| 阶段 | 内容 | 风险 |
|---|---|---|
| 3a | 隐私页 `/privacy`；设置里列本租户成员和显示名；人的档案页出现别人；Google 同意屏幕转正式 | 低：页面和配置为主 |
| 3b | 群里按说话人算：Run、讨论任务记在说话人范围；非主人 @ 没开放的 Bot 只讨论 | 中：改 `BotTeam` 和送达的范围，要回归现有群聊 |
| 3c | 开放设置（存储 + 档案页一栏）；别人的「新建」里能选开放给自己的 Bot；请求人范围的对话和绑定房间；Run 的工具交集和自主程度封顶；主人的用量视图；撤回开放 | 高：新的跨范围读取路径，必须逐处核对不读主人内容 |

3b 先于 3c：开放一对一之前，先堵住群里按房间主人算的那一处。

## 9. 动手前要核对的

- 群里 Bot 回复的模型输入已核对（第 6 节）：有常驻嘱咐，没有 brain 和主人与 Bot 的对话。还要核对群里分派出去的 Run（`startTaskAsBot`）的输入：它在 Bot 的对话里跑，那条对话是主人的，3b 改成记在说话人范围后要确认不再带上主人对话的历史。
- `ConversationStore` 按 `owner + agentId` 唯一：请求人范围里 `agentId` 是别人的 Bot，要确认没有地方假设「对话的 agentId 一定是本范围的 Bot」（例如按 agentId 找 Bot 时用对话主人的范围核对，就会是「Unknown Bot」）。
- 例程、Webhook、Bot 之间的侧线程都只在主人范围里跑，别人碰不到；要确认开放之后也没有入口。
- 「只读」工具的判断用工具清单里的 `capabilities`；要确认本地工具和远程 Toolkit 的清单都如实标了 `write`。

## 10. 验收

- 主人没开放的 Bot，别人在任何地方都看不到、选不到，直接调接口得到「Unknown Bot」。
- 主人开放后，名单里的人在「新建」里能选它，打开的是自己的一条对话；不在名单里的人看不到。
- 请求人的 Run 只能用「请求人选的 ∩ 主人开放的」工具；页面多传的工具被服务端去掉；带写入的工具主人没勾就进不来。
- 请求人的 Run 自主程度不超过 `reply`，开 Run 要请求人批准计划，即使主人给 Bot 设了 `auto`。
- 请求人的对话、未读、摘要都在请求人范围；直接查主人范围的表，看不到这条对话。
- 主人在档案页看到每人的次数和 token，点不进内容；请求人第一次打开时看到说明和隐私页链接。
- Bot 回答别人时，模型输入里没有主人的长期记忆、主人和 Bot 的对话、主人的常驻嘱咐。
- 主人关掉开放后，请求人的对话变只读，标「已不再开放」，已在跑的 Run 跑完，不能再开新的。
- 群里非主人 @ 一位没对这个人开放的 Bot：只得到「只讨论」的回复和一句说明，不记任务、不开 Run、不扣主人的计数。
- 群里非主人对开放给自己的 Bot 点「交给它」：讨论任务记在点的人名下、点的人的范围里，主人的任务板上看不到这件事的内容。
- 主人自己在私聊、群里、例程里用 Bot，和今天一样。
- 隐私页不登录也能打开。

## 11. 待定

1. 「别人看得到的背景」要不要单独一份，还是直接用原背景？（草案：可选，不填用原背景。）
2. 「只读」要不要允许 `network`？读网页需要它，但它也能把东西发出去（例如带参数的 GET）。（草案：允许 `web-search`、`web-fetch` 这类声明为只读的；其余带 `network` 的默认不勾。）
3. 每人每月 Run 上限的默认值：不限，还是给一个保守的数（例如 50）？
4. 请求人能不能把和别人 Bot 的对话里的产物分享回给主人？（草案：不做，要给就在群里发。）
5. 移出租户成员时，这个人和别人 Bot 的对话怎么处理：留给本人（本人已经登录不了）、删除、还是转成主人只能看到用量的归档？放进「加用户」设计一起定。
6. 群里有别人时还用不用常驻嘱咐？（草案：用，并在档案页提醒；另一种是有别人的群里只用「别人看得到的介绍」。）
