## 推荐方向与不可变约束

1. 实现真正的模型生成摘要 + 持久化上下文视图；确定性裁剪仍作为最终硬限制/安全降级，不以它代替 H4。
2. 首版使用同一 Run 的冻结模型，摘要计入 calls/tokens/time/global budget；不引入廉价模型自动分流或新计费系统。
3. 新 Run 按显式策略启用，策略随 Run 冻结；旧 Run/已预留 modelRequest 继续按原始请求恢复，不因升级重新压缩。
4. 保留原始材料、观察、回执、历史快照；摘要仅为派生且不可信的工作上下文，不写入 Brain 或 Bot 长期记忆，不授予新证据/权限。
5. 当前目标、系统规则、活动计划/任务、精确审批版本、工具目录/Grant、执行预算、待处理问题、未决操作、最新关键结果及分页协议不能被模型摘要替换。
6. 引用必须绑定同一 Run/当前允许范围、来源 hash 与截取范围；回读不能访问任意 Run JSON、credentials、隔离回执或更广的历史。
7. 压缩在消费模型请求的持久化预留之前完成；summary/view 与来源绑定，恢复不重算已冻结请求。取消后晚到摘要只结算账目，不能激活视图或复活 Run。
8. 摘要失败、超时、未知结果、预算耗尽都必须有明确结果；不得无上限压缩、自动重试未知结果或把调用当免费维护。

## 工作记忆结构与多任务并发约束（2026-10-21）

用户提出采用“分层索引 + summary + search + 原文”，并明确要求支持多任务并发。这更新了设计约束，不代表详细实施方案已经获批。

- 索引按任务、阶段/子任务、事件/材料组织；summary 是附带来源的派生视图，search 横跨允许的索引、摘要和原文。权威状态与最近关键原文不依赖检索才能恢复。
- 同一 Bot 必须能同时承载多个任务，不能用一份可变 Bot/session 总摘要作为所有任务共享的工作区。区分会话、Run、Run 内子任务/分支及执行尝试；请求的当前任务身份必须显式传递，不依赖进程级 currentTask。
- 每个工作记忆分区拥有独立的索引范围、摘要/视图版本、检索与回读范围、预算归属及恢复点。身份包括 owner/tenant、bot（Bot 层存在时）、thread、run、task/branch 和 generation；具体字段映射须核对现有合约，不提前假设 Bot 层已经实现。
- 搜索授权过滤先于召回、排序、摘要生成及内容返回；不能通过摘要、命中计数或片段泄露另一个任务/Bot 的私有信息。跨任务共享必须通过显式发布的消息或带来源版本的材料引用，并在读取时检查权限；依赖完成不等于拥有对方完整记忆访问权。
- 并发摘要绑定不可变来源清单、精确覆盖范围与摘要操作身份。新增事件追加，不被旧快照摘要覆盖。激活摘要时校验来源、任务 generation 和视图版本，以原子比较更新或现有 fence 保证同一视图不被竞争覆盖；冲突结果保留审计但不盲目激活。
- 并发控制按需要隔离到 Run/工作记忆分区；不增加 Bot 级全局串行锁。多个 Run 可独立执行和压缩。对于现有 Run 内调度，另行核查并行能力，不能把多个 worker 竞争同一 Run 的防重 fence 误称为多个子任务同时执行。
- 压缩、搜索、回读都归属具体任务；并发模型请求须遵守共享资源上限和既有 Run/global 预算预留/结算，不通过各自读取旧余额绕过总预算。某任务的超时、未知结果或取消不应取消其他任务；全局限额触发属于明确的共享约束。
- 共享文件、浏览器会话、数据库等外部资源的写入冲突由执行/资源层处理，不能因记忆分区隔离而宣称副作用天然隔离。操作与回执必须关联发起任务。
- 验收补充：同 Bot 两个任务包含同名但矛盾的事实时不串读；一任务压缩时另一任务正常推进；摘要期间追加内容不丢失；同视图竞争激活至多一个成功；单任务取消和重启恢复不影响另一任务；越权搜索/回读及共享权限撤销被拒绝；并发预算不会重复预留或超额批准。
