# Bot 当成员：私聊和对话合成一件事

## 0. 问题

现在和同一位 Bot 一对一说话有两个地方：

| | Bot 对话（生活线程） | 频道列表里的「私聊」 |
|---|---|---|
| 存在哪 | `aeeis_conversations`，每人每 Bot 一条 | `aeeis_rooms`，`chat: direct` |
| Bot 能做事 | 能：任务、Run、工具、例程、问别的 Bot、交接 | 只能回复（一次模型调用，不能用工具）；要做事走提议和任务板 |
| 例程结果 | 送到这里 | 不送 |
| 成员和角色 | 没有，就你和 Bot | 有成员表、角色，能归档 |

同一段关系，在哪里打开决定了 Bot 能做什么，界面上又看不出来。生产上（2026-11-26）有 8 间活跃的私聊房间，每间只有一位 Bot，没有人和人的私聊。

## 1. 原则

**Bot 尽量像人一样对待。** 人能出现的地方（名单、@、私聊、群聊、档案、在线状态、未读），Bot 都以同样的方式出现。

**一段一对一关系只有一个地方：和这位成员的私聊。** 不论对方是人还是 Bot，入口、样子、读法都一样。

**能做什么取决于「谁」，不取决于「在哪个盒子里」。** Bot 能做的事由它自己的能力和授权决定（工具、自主程度、主人的常驻嘱咐），跟它在私聊还是在群里无关；不同的只是结果给谁看。

## 2. 用户看到的样子

### 2.1 一个「消息」列表

- 左栏只有一个列表：私聊和群聊混排，按最近消息排序。每项是头像、名字、最后一句、未读数。
- 「Bot 对话」不再是单独的一栏：和阿研的对话就是「和阿研的私聊」。
- 人和 Bot 的私聊长得一样。Bot 头像角上有一个小标记表示是 Bot（和飞书、Slack 的 App 标记一样），名字后面可以显示「正在做 2 件」，就像人的状态。
- 点头像打开成员档案。人和 Bot 用同一个档案页；Bot 的档案多几栏：角色和背景、自主程度、工具、例程、和其他 Bot 的侧线程（默认折叠）。

### 2.2 私聊里

- 你说一句，对方回。对方是人就等人回；对方是 Bot 就由 Bot 回，并且**能做事**：开任务、跑 Run、用工具、问别的 Bot、交接。也就是今天 Bot 对话的全部行为。
- 任务、Run、例程结果仍然显示在这段私聊里（今天 Bot 对话里的任务栏、Run 卡片不变）。
- 「新建私聊」选一位成员：选的是 Bot 时打开和它的私聊，已经有就直接打开，不会再开出第二间。

### 2.3 群聊里

- 规则不变（谁回复、@、一个声音、交接、改派，见 2026-10-29 文档）。
- Bot 在群里也是同一个 Bot：它在群里提议、开工，由它的自主程度决定，和人在群里说「这件我来」一样落到任务板。
- 群里 Bot 的回复带一个小注「要它直接办，点『交给它』」，把这句话变成任务，记到这位 Bot 那里（任务板和它的私聊都看得见）。不在群里偷偷开出权限更大的 Run。

## 3. 权限：问三件事

一次 Bot 的动作是否允许、结果给谁看，只看下面三件，和容器无关：

1. **谁在请它做。** Run 的主人是发出请求的人，记在这个人的范围（owner/tenant）里，用这个人的额度。
2. **Bot 自己被允许做什么。** Bot 主人给它的工具授权、自主程度和常驻嘱咐。请求的人不能给 Bot 加权限，只能在这之内请它做。
3. **在哪里说的，决定谁看得见。** 私聊里只有两方看得见；群里按房间成员和隐私设置。

今天的规则大多已经是这样，变化是：私聊里的 Bot 不再因为「房间」被降成只能讨论。

## 4. 数据怎么存（不迁 Run）

- **和 Bot 的私聊沿用对话（生活线程）存储。** 任务、Run、工作记忆、例程都挂在它上面，不动。
- **人和人的私聊、群聊沿用房间。**
- 加一层很薄的「聊天」投影给列表用：`{ id, kind: direct|group, counterpart?, title, lastMessage, unread, updatedAt, backing: conversation|room }`。界面只认这一层，打开时再按 `backing` 走各自的接口。
- 新建私聊时对方是 Bot：服务端返回（或建立）那条对话，不再建 `chat: direct` 的房间。直接用 API 建「只有一位 Bot 的私聊房间」返回 409，并指向那条对话。
- 侧线程（Bot 和 Bot 之间的私聊）仍是房间，只在 Bot 档案里显示，不进消息列表。

## 5. 旧私聊房间的迁移

生产上 8 间，都是「主人 + 一位 Bot」。

1. 每间的消息按时间复制到这位 Bot 的对话里，标成「来自旧私聊」的历史，只读，不触发回复，不进任务；幂等键 `legacy-direct:<room>:<event>`。
2. 房间归档，标题后加「（已合并到私聊）」；打开旧链接跳到对应的对话。
3. 房间里的任务板卡片（提议、交接中）不迁：迁移前列出来给主人看，没有的话直接归档。
4. 先只读统计每间的消息数、卡片数，再在没有 Run 运行时执行；可以回滚（取消归档，删掉标了来源的历史）。

## 6. 阶段

| 阶段 | 内容 | 风险 |
|---|---|---|
| 1 | 统一列表和档案：一个消息列表，人和 Bot 同样显示；新建私聊选 Bot 时打开对话；服务端拒绝新的「只有 Bot 的私聊房间」 | 低，只动界面和一个入口 |
| 2 | 迁移 8 间旧私聊房间（第 5 节） | 中，动生产数据，要主人同意、选时间 |
| 3 | 群里「交给它」按钮和回复小注 | 低 |
| 4 | 多人：别人也能私聊你的 Bot。每人和每位 Bot 各一条对话（今天已经按 owner+agent 存），Run 用请求人的范围和额度，Bot 主人看不到别人的私聊内容，只看到用量 | 中，跟「加用户」一起做 |

阶段 1 做完，用户就只有一个地方和 Bot 一对一说话；后面三个阶段各自独立。

## 7. 不在范围

- 群聊的回复规则、交接、改派、任务板，照 2026-10-29 文档。
- 人和人私聊的新能力（比如私聊里的任务板）。
- 飞书私信：照旧写进和 AEEIS 的私聊（就是今天的对话）。

## 8. 验收

- 消息列表里，和 Bot 的私聊与和人的私聊样子一样，能看出哪位是 Bot；一位 Bot 只有一段私聊。
- 在和 Bot 的私聊里能开任务、跑 Run、收到例程结果，和今天的 Bot 对话完全一样。
- 新建私聊选一位已有私聊的 Bot，打开原来那段；API 不能再建出只有一位 Bot 的私聊房间。
- 迁移后旧私聊房间都已归档，旧链接打开对应的私聊，历史可读、不触发回复；重跑迁移不会重复。
- 群里的行为和今天一样。

## 9. 待定

1. 列表叫「消息」还是沿用「对话」？
2. 迁移时旧私聊房间里的历史要不要带过来，还是只归档、留链接？
3. 阶段 4 里，Bot 主人能否给「别人请它做的事」另设更紧的工具范围？
