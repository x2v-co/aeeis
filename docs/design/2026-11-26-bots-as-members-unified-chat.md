# Bot 当成员：一个「消息」列表

## 0. 现在已经是什么样

数据层面，「私聊」和「Bot 对话」已经是一件事（统一数据流 PR2，#177）：

- 每位 Bot 有一条对话（生活线程，`aeeis_conversations`，按主人范围 + agentId 一条）和一间「私聊」房间（`chat: direct`），两者由 `aeeis_bot_dialogues` 绑定。生产上（2026-11-26）8 位 Bot 各一条绑定，全部 `ready`，没有冲突，也没有未绑定的私聊房间。
- 往对话写消息前先检查绑定的房间可写（`BotDialogueService.conversationWrite` → `assertRoomEventWriter`），房间是这段关系的地址。
- 界面打开一间绑定的私聊房间，会直接跳到这位 Bot 的对话（`openGroup` → `openLifeThread`）；群聊里的「只讨论」回复逻辑跳过绑定的房间（`BotTeam` 的 `dialogueRoom`）。所以在私聊里 Bot 已经能开任务、跑 Run、用工具、问别的 Bot、交接。

还没统一的是**界面**：

| | 今天 |
|---|---|
| 左栏 | 「Bot」一栏（对话）和「群聊」一栏分开 |
| 绑定的私聊房间 | 不在群聊栏里，但还出现在「频道管理」和名册的房间链接里，点开再跳回对话 |
| 未读 | 没有，代码里没有任何已读记录 |
| 档案 | Bot 有「关于它」面板；人没有对应的档案页 |
| 群里请 Bot 做事 | 只能提议、等自主程度决定；没有一键把一句话交给它 |

## 1. 原则

- **Bot 尽量像人一样对待。** 名单、私聊、群聊、档案、状态、未读，人和 Bot 一样出现。
- **一段一对一关系只有一个入口。** 和一位 Bot 的一对一就是它的对话；绑定的房间只是它的地址，不单独露出来。
- **能做什么取决于「谁」，不取决于「在哪里」。** 见第 3 节。

## 2. 要做的事

### 2.1 一个「消息」列表（阶段 1）

- 左栏「Bot」和「群聊」两栏合成一个「消息」列表，按最近消息排序。每项：头像、名字、最后一句、未读数；Bot 头像角上一个小标记，名字后可显示「正在做 2 件」。
- 列表由一个只读投影供给：`{ id, kind: direct|group, counterpart?, title, lastMessage, unread, updatedAt, backing: conversation|room }`。和 Bot 的一项指向对话（`backing: conversation`），群聊指向房间。
- 绑定的私聊房间不进列表，也从「频道管理」和名册的房间链接里拿掉（侧线程今天已经这样处理）。旧链接照旧跳到对话。
- 「新建」里选 Bot 就打开它的对话；选人建群聊。不新增给用户直接建私聊房间的入口。若要在服务端拦，只拦公开的建房接口，不能碰 `ensureDialogueRoom`（绑定靠它建房）。

### 2.2 未读（阶段 1，新功能）

今天没有已读记录，这是新做的，不是投影顺带的：

- 每人每个聊天记一个「读到哪条」：对话按消息序号，群聊按房间事件序号。打开聊天、滚到底时更新。
- 未读数 = 最新序号之后、不是自己发的消息条数；Bot 自己的工作过程（Run 卡片、步骤）不算未读，只有它说的话算。
- 投影的「最后一句」也要从两处取：对话取最后一条消息，群聊取最后一条房间消息。

### 2.3 一个档案页（阶段 1）

- 点头像打开成员档案，人和 Bot 同一个页面。Bot 多几栏（就是今天「关于它」的内容）：角色和背景、自主程度、工具、例程、和其他 Bot 的侧线程（默认折叠）。

### 2.4 群里「交给它」（阶段 2）

- 群里 Bot 的回复下有「交给它」：把这句话变成一个任务，记到这位 Bot 的对话里，用说这句话的人的范围和额度；任务板和 Bot 的对话都看得见。
- 不在群里直接开出权限更大的 Run；群里照旧按 2026-10-29 文档的规则回复、提议、交接。

## 3. 权限：问三件事

一次 Bot 的动作是否允许、结果给谁看，只看：

1. **谁在请它做。** Run 记在请求人的范围里，用请求人的额度。
2. **Bot 被允许做什么。** 主人给它的工具授权、自主程度和常驻嘱咐；请求人不能加权限。
3. **在哪里说的，决定谁看得见。** 对话里只有两方；群里按房间成员和隐私设置。

今天只有主人自己能用自己的 Bot，三件事落在同一个人身上。别人用你的 Bot 见第 6 节。

## 4. 不做的事

- 不迁数据、不归档绑定的私聊房间：房间是绑定的地址，归档后它变成只读，对这位 Bot 的每一次写入都会被拒绝。
- 不复制历史：绑定建立时已经整理过房间历史（`aeeis_bot_dialogue_operations` 已完成）。
- 不改群聊的回复规则、交接、改派、任务板。
- 不做人和人的私聊（今天每个工作区只有主人一个人）。
- 飞书私信照旧写进和 AEEIS 的对话。

## 5. 阶段

| 阶段 | 内容 | 风险 |
|---|---|---|
| 1 | 「消息」列表 + 未读 + 同一个档案页；绑定房间从频道管理和名册里隐去 | 中：未读是新的数据和写入路径；其余只动界面 |
| 2 | 群里「交给它」 | 低 |
| 3 | 别人也能和你的 Bot 说话（第 6 节，单独设计） | 高，跟「加用户」一起做 |

## 6. 以后：别人和你的 Bot 说话（单独设计）

今天做不到，不是差一张表：对话和 Bot 都按主人范围存，绑定服务对非主人直接返回「Unknown Bot」。要让别人用，需要单独设计：

- Bot 的常驻嘱咐、记忆、工具授权在主人范围里，Run 记在请求人范围里——跨范围读哪些、写哪些。
- 每个请求人和这位 Bot 各一条对话，存在谁的范围里；主人能看到什么（用量，不看内容）。
- 已定：主人可以另设「对别人开放的工具」，默认只读；不在其中的工具被拒绝并说明原因。

这部分和「加用户」、隐私页一起写成单独的设计文档。

## 7. 验收（阶段 1、2）

- 左栏只有一个「消息」列表，Bot 和群聊混排；能看出谁是 Bot；一位 Bot 只有一项。
- 频道管理和名册里不再出现绑定的私聊房间；旧房间链接打开对应的对话。
- 未读数在收到别人或 Bot 的新话时增加，打开读到底后清零；Run 步骤不计未读；刷新、换设备后一致。
- 人和 Bot 点头像打开同一个档案页。
- 群里点「交给它」后，任务出现在这位 Bot 的对话和任务板，记在点的人名下。
- 对话里开任务、跑 Run、收例程结果、群里的行为都和今天一样。

## 8. 已定（2026-11-26）

1. 列表叫「消息」。
2. 旧私聊房间不归档、不复制历史：它们是绑定的地址，已经和对话是同一份数据（第 0、4 节）。
3. 别人请 Bot 做事时只用主人设的「对别人开放的工具」，默认只读（第 6 节，以后做）。
